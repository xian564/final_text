# 20 · 蓝色识别丢失排错（色相空档 + 低照度）

## 现象
- 蓝包 `blue_guard` 部分帧完全无红框；
- 有框帧也常只有单根灯条，配不成装甲；
- 降采样到 640 时蓝色几乎全灭（已确认）。

## 排查步骤

### 1. 先排除“画框干扰”
最初在 `docs/attempts` 调试图上统计 HSV，发现 H≈60/30 的像素很多，
后来确认那是**自己画的绿框/黄框**，不是灯条。改为抓取**未标注的原始帧**：

```bash
rosbag play bag/blue_guard.bag --clock -l
# 订阅 /hk_camera/image_raw/compressed 存帧
```

### 2. 统计亮像素色相（原始帧，V>150）

| 帧 | 亮像素数 | 色相 Top |
|---|---|---|
| r_0 | 518 | H≈90~94（40/32/29），少量 104 |
| r_1 | 502 | H≈90~95，少量 112~114 |

### 3. 对比掩膜覆盖

| 掩膜 | 像素数 | 最大连通域 |
|---|---|---|
| 蓝 H100~140（旧） | 463 | 78 px |
| 蓝 H85~140（新） | 806 | 204 px |
| 青 H80~100 | 314 | 92 px |

**根因：蓝灯过曝后色相从 H≈110 滑到 H≈90（青色），
旧阈值从 H=100 才开始，正好把灯条核心丢掉；而绿色掩膜只到 H=70，
H 85~99 成了两侧都覆盖不到的空档。**

另外蓝包整体极暗：全帧 V>150 仅约 500 像素，灯条只有几十~两百像素，
所以稍微丢一点就配不成对。

## 修改位置（数据位置）

文件：`src/detection_node_v3.cpp`

| 行号 | 参数 | 旧值 | 新值 |
|---|---|---|---|
| 89 | `blue_h_min` | 100 | **85** |
| 91 | `blue_s_min` | 50 | **30** |

掩膜实际使用处：
- `src/detection_node_v3.cpp:272`（colorSegment 蓝色通道）
- `src/detection_node_v3.cpp:351`（近战重分割蓝色通道）

调参入口（无需改代码）：
```bash
rosrun final_text detect_node_v3 _blue_h_min:=85 _blue_s_min:=30
```

## 验证
```bash
rosrun final_text detect_node_v3 _blue_h_min:=85 _blue_s_min:=30
```
20 秒蓝包：
- 检测 20 次
- Hold 11 次（原 19）
- 异常 0
- 帧命中率 **95/115 = 82.6%**（原约 48%）
